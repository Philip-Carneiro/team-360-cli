# Contributing to team-360-cli

Thanks for your interest in contributing. This document covers the rules and workflow.

## Rules

1. **No direct commits to `main`** — the pre-commit hook blocks this. All changes go through Pull Requests.
2. **All commits must be signed** (`git commit -s`) — adds a `Signed-off-by` line (DCO). The pre-commit hook blocks unsigned commits.
3. **All code must pass lint and format checks** — `ruff check` and `ruff format` run automatically on every commit via pre-commit hooks. Zero warnings, zero errors, or the commit is blocked.
4. **PRs require review and approval** from a maintainer before merging.

## Workflow

### 1. Fork the repository

Go to [github.com/Philip-Carneiro/team-360-cli](https://github.com/Philip-Carneiro/team-360-cli) and click **Fork**.

### 2. Clone your fork and set up

```bash
git clone https://github.com/YOUR-USERNAME/team-360-cli.git
cd team-360-cli
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pip install ruff pre-commit
pre-commit install --hook-type pre-commit --hook-type commit-msg
```

### 3. Create a feature branch

```bash
git checkout -b feature/your-feature
```

### 4. Make your changes

Follow the conventions below. Run lint and format manually if you want to check before committing:

```bash
ruff check .        # lint
ruff format .       # format
```

### 5. Commit with sign-off

```bash
git commit -s -m "Add support for custom report templates"
```

The `-s` flag adds `Signed-off-by: Your Name <your@email.com>` to the commit message. This is required.

On commit, the pre-commit hooks will automatically:
- Run `ruff check --fix` on modified files (auto-fixes what it can)
- Run `ruff format` on modified files
- Verify the commit is signed
- Block the commit if on `main` branch

If any check fails, the commit is rejected. Fix the issues and try again.

### 6. Push and open a Pull Request

```bash
git push origin feature/your-feature
```

Then open a PR from your fork to `Philip-Carneiro/team-360-cli:main`. All PRs require review and approval before merging.

## Setting Up Signed Commits

### Option A: Sign-off only (DCO)

The `-s` flag on `git commit` is the minimum requirement. To make it automatic:

```bash
git config --global format.signoff true
```

### Option B: GPG-signed commits (recommended)

```bash
# Generate a GPG key
gpg --full-generate-key

# Get your key ID
gpg --list-secret-keys --keyid-format=long

# Configure git to use it
git config --global user.signingkey YOUR_KEY_ID
git config --global commit.gpgsign true

# Add the public key to GitHub
gpg --armor --export YOUR_KEY_ID
# Paste at: GitHub > Settings > SSH and GPG keys > New GPG key
```

## Project Structure

```
team-360-cli/
  main.py              # CLI entry point and orchestration
  config.py            # Team configuration parser (markdown + Confluence)
  heuristics.py        # Analysis engine (stale detection, workload, risks)
  report.py            # Markdown report generator
  setup.py             # Interactive env var setup wizard
  teams.example.json   # Example team config (teams.json is generated by --setup)
  examples/            # Example Confluence page formats
  collectors/
    jira.py            # JIRA board, backlog, bugs, strats, epics
    github.py          # GitHub PR collection (via gh CLI)
    gitlab.py          # GitLab MR collection (via glab CLI)
    calendar.py        # Google Calendar PTO/absence collection
  publishers/
    confluence.py      # Confluence REST API publisher
    vault.py           # Obsidian vault file writer
```

## Linting & Formatting

This project uses [ruff](https://docs.astral.sh/ruff/) for both linting and formatting. Configuration is in `pyproject.toml`.

```bash
# Check for issues
ruff check .

# Auto-fix what it can
ruff check . --fix

# Format code
ruff format .

# Check format without changing files
ruff format --check .
```

## Conventions

- **Python 3.10+** — use type hints, f-strings, `Path` over `os.path`
- **No unnecessary dependencies** — if the stdlib or `requests` can do it, don't add a package
- **Credentials from env vars only** — never hardcode tokens, URLs, or secrets
- **No comments unless the "why" is non-obvious** — let clear naming do the work
- **Test with `--test` mode** before submitting — verify the report generates without errors
- **All code must pass `ruff check` and `ruff format`** with zero warnings and errors

## Adding a New Collector

1. Create `collectors/your_source.py` with a `collect_*` function that returns structured data
2. Import and call it in `main.py` (add to the parallel collection block)
3. Handle the data in `heuristics.py` if analysis is needed
4. Add the relevant section in `report.py`

## Adding a New Publisher

1. Create `publishers/your_target.py` with a publish function
2. Call it from `main.py` after report generation
3. Add any required env vars to `setup.py`'s `ENV_VARS` list

## Code of Conduct

Be respectful. Be constructive. Focus on the work. We're here to build useful tools, not to argue.
